## Intent

Continue qualifying the capture-to-physical-print path on the owner's iPhone 15 Plus, Bluefy, and Instax Mini Link 3 while integrated development proceeds with a simulated printer. At design approval, a new fresh-film pack had been loaded as of 2026-10-13. The later fresh-film and used-film outcomes are recorded separately in the [current trial report](../../qualification/issue-17-trial-report.md). Record the actual iOS, Bluefy, and printer firmware versions at each new trial rather than relying on previously reported versions.

The output is a pass-or-fail record for every original issue #17 criterion, the observed printer signal sequence, and a conclusion about whether normal physical film ejection can be distinguished from command acceptance. The result informs the physical completion checkpoint in [ADR-0021](../../adr/0021-move-print-qualification-to-integration-checkpoint.md); it no longer controls when integrated development starts. The actual iPad A16 trial in issue #7 remains the first-release **launch** gate.

## Scope and boundaries

Build one isolated, supervised HTTPS qualification page. It has an operator setup view and a compact trial flow that exercises camera preview, Capture, Retake, printable crop, and Print on the iPhone. Its local allowance starts at three qualification prints. The operator can see timestamped printer diagnostics and a clear pending, ejected, rejected-before-film, or uncertain outcome. The trial flow must not be presented as an unattended Booth Mode or as a supported iPhone product feature.

The harness does not create Events, Guest Sessions, Test Prints, Print Attempts, Print Reservations, Film Reservations, Film Stock entries, Booth Access Grants, or Supabase records. Qualification sheets are counted manually outside product accounting. Photos remain in browser memory for the current trial capture and direct printer transfer; the harness never uploads, stores, logs, or exports photo bytes. Exportable diagnostics contain non-photo event metadata only. A reload may lose the photo and local counter; the operator reconciles the physical sheets before restarting a run.

Use the [design system](../../../DESIGN_SYSTEM.md) for the compact controls and truthful status presentation. The preview is mirrored for positioning; review shows the unmirrored image and the exact portrait crop sent to the printer. The main Capture, Retake, and Print actions fit the usable iPhone viewport and remain operable under browser chrome and Guided Access. Printer pairing, permission prompts, and fault details belong to the supervised operator setup, not to a Guest-facing step.

## Harness components and data flow

1. **Operator setup:** Show HTTPS/browser capability, camera permission, printer connection, current printer status, local allowance, and a start/reset control. Pairing and permission grants happen here. Reset requires the operator to compare the on-screen counter with the physical sheets used; it never silently restores allowance after an uncertain command.
2. **Capture and crop:** Keep camera frames and the selected photo in memory. Capture an unmirrored still from the mirrored preview. Retake replaces the selected photo without using allowance. Review displays the final portrait crop and orientation before Print. Image encoding is behind a small printer adapter; any format or protocol value borrowed from earlier experiments is a hypothesis until physical output verifies it.
3. **Printer adapter:** Separate connection, image transfer, command acknowledgement, raw status notifications, and disconnect detection. It logs status codes and timing, never image-transfer payloads, without calling an acknowledgement or Film Remaining change an ejection. The trial identifies which, if any, observed signal or sequence reliably marks physical ejection. The full application's eventual adapter contract is defined in issue #9 from that evidence.
4. **Local attempt controller:** Allow only one print command at a time and disable duplicate submission. After the command is sent, keep the attempt pending until evidence supports ejection or a clear pre-film rejection. A timeout, disconnect, reload, or ambiguous response after possible command delivery becomes **uncertain**; block further printing and never resend automatically. The local allowance advances only for a verified qualification ejection. An uncertain outcome requires physical inspection and manual run reconciliation.
5. **Evidence log:** Give each run and print attempt an ID. Record wall-clock timestamps and elapsed milliseconds for user action, image preparation, transfer, command acknowledgement, raw status changes, disconnects, and the controller's outcome. Record no image data or Guest identity. The operator adds the observed physical ejection time and sheet result to the trial record so the raw timeline can be compared with the printer.

## Trial sequence

The operator prepares a trusted HTTPS address valid on the iPhone, confirms a fresh usable pack is loaded, records the actual device/browser/firmware versions, and starts a new evidence run. A second camera recording the iPhone and printer together is preferred for correlating status with physical ejection; if unavailable, the observer writes the times and observations during the run.

First, without sending a print command, verify pairing and camera/Bluetooth permissions during setup; mirrored preview, Capture, Retake, unmirrored review, crop framing, and compact controls; fullscreen/browser-chrome behavior; and Guided Access restrictions. Verify that a Guest cannot use browser or device navigation to leave the trial flow. The harness contains no Admin pages; access to protected Admin routes is verified later in the integrated product. Disconnect the printer **before** a command, show the blocked state, reconnect during operator setup, and verify that recovery never sends a queued or duplicate command. Keep the printer connected to continuous power for the physical-print sequence.

Then run three consecutive successful physical qualification prints through the capture-to-print flow. At least one run includes a Retake. For each attempt, record the command/status timeline, observed physical ejection, and the printed crop and orientation. The print is not counted as successful merely because the command was acknowledged or Film Remaining changed. After the third verified print, show zero local allowance and demonstrate that a fourth Print cannot be sent. No extra physical sheet is needed for the exhaustion check.

If a command may have reached the printer but its outcome is unclear, stop the sequence, mark it uncertain, inspect the printer, and record the physical result. Do not automatically resend or count that run as a pass. A failed physical print or ambiguous normal-completion signal means the three-print passing sequence must be repeated after the cause is understood; the existence of a loaded pack does not waive a criterion.

## Evidence and gate decision

| Criterion                         | Evidence required for a pass                                                                                                                                                                                                            |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Test setup                        | Actual iPhone model, iOS, Bluefy, printer model/firmware, trusted HTTPS context, and loaded usable film recorded at trial time.                                                                                                         |
| Permissions and guest restriction | Operator grants camera/Bluetooth permissions before the trial flow; Guided Access and browser navigation checks show that a Guest cannot leave the intended flow.                                                                       |
| Combined operation                | Camera preview, fullscreen/usable viewport, Bluetooth connection, capture, and printing work together without a Guest permission prompt.                                                                                                |
| Image output                      | Each of three physical sheets matches the reviewed unmirrored portrait crop and orientation.                                                                                                                                            |
| Three prints and Retake           | Three consecutive physical Guest-flow prints eject; at least one flow includes a Retake; each sheet and attempt has a distinct log entry.                                                                                               |
| Allowance                         | After three verified prints, the local counter is zero and another Print command cannot be sent. Retake consumes no allowance.                                                                                                          |
| Disconnect and power              | A pre-command disconnect blocks printing; operator reconnection restores the flow without an automatic send. The physical-print sequence works while the printer has continuous power.                                                  |
| Physical-ejection feedback        | A reproducible completion signal or sequence is correlated with observed film ejection for all three prints, remains distinct from command acceptance and Film Remaining alone, and never declares completion before observed ejection. |
| Fault handling and privacy        | An ambiguous post-command outcome remains uncertain and cannot auto-resend; diagnostic output contains no photo bytes, and no Guest photo is persisted or uploaded.                                                                     |

Record pass, fail, or not observed for each row, with the run IDs and evidence links or notes. **The original automatic-detection trial passes only if every criterion passes and normal film ejection has reliable, distinguishable feedback.** A missing or ambiguous ejection signal fails that trial even if the sheets physically print. A supervised/manual production option requires a separate explicit design and validation decision. Post a concise trial report and non-photo diagnostic timeline to issue #17. Do not close or mark automatic detection proven until the physical evidence is reviewed.

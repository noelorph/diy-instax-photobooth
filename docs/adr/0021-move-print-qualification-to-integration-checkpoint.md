# Move remaining print qualification to an integration checkpoint

> **Current scope (2026-10-21):** Integration staging remains; a routine manual-production completion alternative is superseded. Automatic normal full ejection is mandatory; phone inspection is exceptional recovery only. [ADR-0025](0025-package-accounting-and-booth-recovery.md) and the [replacement contract](../superpowers/specs/2026-10-21-package-accounting-booth-recovery-design.md) control conflicting behavior. The original decision below is retained as history.

The October 2026 iPhone trials established that Bluefy can capture and send images to the Mini Link 3, that seven fresh-film prints matched their reviewed crop and orientation, and that a separate three-sheet used-film run exercised Retake, local allowance exhaustion, and a blocked fourth trial. The printer's film count and `12 7f` status field correlate with printing, but neither has been proven to indicate **complete physical ejection** reliably. Used sheets cannot qualify fresh-film image output. See the [issue #17 evidence report](../qualification/issue-17-trial-report.md).

Integrated Admin and Booth development may begin with a simulated printer and a replaceable browser-side printer adapter. Print outcomes must distinguish command acceptance, observed physical ejection, clear pre-film rejection, and uncertainty. No command acknowledgement, film-count change, or unverified status field may create a Confirmed Print. An uncertain attempt must not be automatically resent; its reservations remain held until the Admin resolves it. Development tests may use provisional printer feedback, but must not present it as a hardware guarantee.

**Before completing or enabling printer-backed Live Event Booth Mode, Test Prints, stock consumption, and Confirmed Print accounting**, the project must make and validate an explicit ejection-confirmation decision. Reliable automatic detection remains the preferred path and should continue to be investigated with fresh film. If it remains unproven, a supervised/manual confirmation approach may be considered, but its actors, guest and Admin behavior, timing, failure recovery, authorization, accounting effects, and physical validation must be decided and documented before it can satisfy this checkpoint. Merely tapping the qualification harness's observation button does not establish an automatic printer signal or approve a production manual workflow.

The iPad A16 trial remains a separate release gate. No first-release direct browser printing or Event launch is approved until the chosen completion approach and the complete Booth flow pass on the actual iPad with usable fresh film. The iPhone remains a development/test device. The independent operational decisions raised in [issue #8](https://github.com/noelorph/diy-instax-photobooth/issues/8) are resolved and recorded in [ADR-0014](0014-stop-booth-before-print-reservation.md) and [ADR-0016](0016-keep-history-when-deleting-draft.md); implementation must preserve them.

This decision supersedes the **development-timing and pre-build qualification clauses** in [ADR-0012](0012-qualify-development-on-iphone-before-ipad-launch.md) and the related timing clause in [ADR-0005](0005-validate-the-target-booth-browser.md). It does not declare the original iPhone qualification gate passed, change the definition of a Confirmed Print, or weaken the iPad release gate.

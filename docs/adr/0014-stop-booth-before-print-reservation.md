# Stop Booth Mode safely before a Print Reservation

> **Current scope (2026-10-21):** Same-photo retry and pause sign-in recovery are superseded; the new contract defines stop-versus-dispatch races. [ADR-0025](0025-package-accounting-and-booth-recovery.md) and the [replacement contract](../superpowers/specs/2026-10-21-package-accounting-booth-recovery-design.md) control conflicting behavior. The original decision below is retained as history.

An Admin pause or Event completion from another device stops a Guest in preview, countdown, or review before any Print Reservation exists. The booth discards an unprinted photo, keeps completed Captures, and shows a generic protected handoff; a countdown stopped before the shutter has no Capture. The server orders the stop and reservation creation so a stopped booth cannot send a print, while a reservation made first delays pause or blocks completion until its outcome is recorded or resolved. A paused Live Event can resume only after Admin sign-in; a Completed Event cannot resume. This uses the existing Booth Access Grant and reservation boundary without retaining a Guest photo across sign-in.

A clear pre-film rejection releases its holds. If the booth remains active and ready, the Guest may explicitly retry the selected photo still in browser memory through a new Print Attempt. Failed readiness pauses the booth, discards the photo, and needs Admin recovery before a new Guest Session; an uncertain outcome needs Admin inspection. Neither causes an automatic resend. This preserves the current Guest Session without an Admin handoff for a verified, recoverable rejection. These rules extend [ADR-0001](0001-do-not-retain-guest-photos.md), [ADR-0002](0002-isolate-booth-access-from-admin.md), and [ADR-0003](0003-reserve-print-allowance-before-printing.md).

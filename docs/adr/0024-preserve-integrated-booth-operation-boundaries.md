# Preserve integrated Booth operation boundaries

> **Current scope (2026-10-21):** Historical implementation at issue #9 only. Old test/stock/refund/redaction and reconnect revocation are superseded; metadata-only journaling, one-send, origin checks and bounded Capture reconciliation remain as specified in the replacement contract. [ADR-0025](0025-package-accounting-and-booth-recovery.md) and the [replacement contract](../superpowers/specs/2026-10-21-package-accounting-booth-recovery-design.md) control conflicting behavior. The original decision below is retained as history.

**Date:** 2026-10-18. Implemented for local simulated operation; physical printer completion remains gated.

A detected printer connection change stops browser sends and invalidates setup evidence. The server conservatively changes a pending Reserved or Accepted attempt to Uncertain, retains its holds, pauses the run, and revokes its grant. Recovery requires Admin sign-in, resolution of pending reservations, a fresh Test Print and usable-output inspection for the new connection, and an explicit Resume with a new grant. A deliberate protected pause instead records `PauseRequested` while a reserved attempt finishes: new Guest work stops, but the matching attempt may still report its outcome. The run pauses and its grant revokes after that outcome, including uncertainty. This distinction preserves pending feedback without treating reconnection as proof that a command was unused.

The single printer is shared globally. A Test reservation is excluded while any Booth run is Prepared, Active, or PauseRequested, and only one unresolved attempt may hold the printer. A successful Test requires a separate, immutable Admin inspection of usable output bound to that Test attempt and its tested connection; reporting ejection alone does not establish readiness. Reconnection requires new evidence. A contradictory later inspection cannot overwrite the recorded result.

A shutter already fired when a stop wins the race may report one delayed Capture containing metadata only. This exception requires the original unexpired grant proof, a matching just-abandoned Guest Session closed at grant revocation, a capture timestamp between session creation and revocation, and receipt within two minutes after revocation. At most one new delayed Capture is accepted per Session; stable operation keys replay the same result without another count. The exception never reopens a Session, restores a photo, reserves a print, or restores revoked operational authority.

The browser persists stable operation keys and non-photo Capture/reservation metadata before a reservation request can commit. It saves the returned attempt before sending, checks stop and connection state at the send barrier, and invokes the adapter once for that attempt. Failure to persist blocks sending. Reload recovery reconciles the journal and reports uncertainty where command delivery cannot be ruled out; it never resends a pending job automatically. Guest photo bytes remain in memory only.

Operation requests compare the browser Origin with the validated configured public `ADMIN_AUTH_ORIGIN`, also used for Auth recovery. It must be an HTTPS origin with no credentials, path beyond `/`, query, or fragment; HTTP is allowed only for `localhost` and `127.0.0.1`. Invalid configured values fail closed. When unconfigured, operation validation falls back to the request URL's origin; local setup should configure the browser's actual origin because an internal server URL can differ. Forwarded headers cannot select the canonical origin. Cross-site requests are refused.

These refinements extend [ADR-0014](0014-stop-booth-before-print-reservation.md), [ADR-0022](0022-centralize-accounting-transitions-and-persist-pause-requests.md), and [ADR-0023](0023-use-a-single-booth-page-route.md); none is superseded. The approved issue #9 spec remains unchanged. The simulator requires explicit nonproduction opt-in. [ADR-0021](0021-move-print-qualification-to-integration-checkpoint.md), the [issue #17 evidence](../qualification/issue-17-trial-report.md), and the actual-iPad release gate remain in force: simulated ejection, acknowledgements, and printer film counts do not qualify physical completion or inventory.

## Interrupted authority and ambiguous operation recovery

A current provisioned Admin may use `POST /api/admin/print-attempts/{attemptId}/recover` with an operation key and explicit recovery reason to move exactly one Reserved or Accepted Guest or Test attempt to Uncertain when its originating browser, Booth proof, or initiating Test session cannot report. The operation locks Event, stock, then attempt, checks current Admin authority before receipt replay, records one outcome and activity per operation, and retains every hold and the printer slot. A matching Guest run pauses and its grants revoke. It sends no command and never infers unused film. The Admin can reach older attempts through pagination and then use the separate inspected resolution. Original grant expiry and initiating-session observation restrictions remain strict.

Inspected ejected resolution, for both Guest and Test attempts, requires nonproduction simulator opt-in at the route and simulated completion policy in the database. The disabled production policy cannot create a new consumption through Admin recovery. Unused resolution remains available. These restrictions preserve ADR-0021; this does not approve a manual production completion workflow.

Known domain rejections retain their 400/401/403/409 responses. Unknown transport, RPC, or post-commit result-read failures return the safe `operation_unavailable` 503 contract. For stock and Additional Prints additions, the Admin panel retains each original request payload and operation key in memory and exposes an explicit retry even after another action or form edits. A retry reuses the receipt; an ambiguous response is never evidence that an addition failed to commit. This extends ADR-0022's idempotency contract without changing the approved spec or its domain transitions.

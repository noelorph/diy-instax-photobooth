# ADR-0032: Build full F2 while keeping uploads unavailable

**Status:** Accepted implementation scope, milestone prerequisites and final #30 completion order; runtime re-enablement and full F2 acceptance remain blocked on proof.
**Date:** 2026-10-27
**Refines:** [ADR-0027](0027-draft-only-event-media.md), [ADR-0030](0030-fence-event-media-commits-and-require-cleanup-proof.md) and [ADR-0031](0031-temporarily-disable-event-media-uploads.md).
**Supersedes:** ADR-0031's deferral of full F2 implementation and its cleanup-proof prerequisite for writing the dormant editor/private-delivery code. It also replaces full #30 closure as a prerequisite to F3–F8 with the verified upload-disabled F2 milestone, allowing F8 disabled-scope completion. It does not supersede runtime unavailability, trusted denials, cleanup proof, private access, retention or hardware gates.
**Approval:** The user clarified: “Keep uploads unavailable but build to complete the original F2.” The user also requested a visible Admin Event Media reminder about unresolved late-upload and leftover-file cleanup, then clarified that other #10 work should continue while complete media cleanup waits. The user selected keeping #30 inside #10 and finishing it last.

## Context

F2 has verified local disabled-scope implementation on `9d6286f`; its [dated acceptance record](../implementation/issue-30-disabled-media-acceptance.md) remains unchanged. That result does not complete original #30. The scoped Storage commit guard rejects the reproduced late metadata commit, but transfer inventory/drain and removal of all backend files remain unproven. These failures cannot be converted into acceptance by completing UI code.

## Decision

- Restore the original full Event preparation/private media capability as F2/#30's tracking and implementation target. Build the remaining editor, resumable-transfer integration, validation/revision/receipt handling and authorized private delivery as dormant code using the existing plan/interfaces, sections/designs and assets. Retain Draft-only mutation, content limits and unchanged-current-media-on-failure rules. This authorizes implementation, not an enabled product workflow or a claim that the code already exists.
- Keep product upload authorization and upload/attachment/replacement mutations denied at trusted boundaries. Preserve accessible unavailable sections and disabled controls. Dormant code must not provide a bypass, issue usable credentials or weaken the current availability boundary. Authorized existing-media reads/removal/cleanup and receipt recovery retain their existing safety rules. Default Booth presentation remains usable without optional media.
- On the Admin Event Media page, show persistent readable copy alongside the unavailable status: **“Before re-enabling uploads, verify cleanup of interrupted or late uploads and leftover files.”** Keep this visible even when no media is attached. This is a reminder of unresolved work, not a cleanup action, a completion claim or a re-enable control.
- Keep media-bearing Draft deletion pending until supported proof establishes a complete authorized-transfer inventory, termination/drain, removal of all backend object versions, staging bytes and metadata, and a final rescan. Listing emptiness, denied downloads, application expiry, vendor replies, isolated proof or disabled uploads alone do not establish this. Preserve ADR-0030's scoped guard and original deletion receipt recovery; retained Live/terminal media is not abandoned-upload cleanup.
- Full #30 completion still requires the original content/size/duration, interrupted transfer/response-loss, failure, stale/concurrent replacement, Start/Cancel/revocation, cleanup/no-resurrection and private-delivery/renewal proofs, plus supported-device private playback qualification. Record dormant-code verification separately from enabled end-to-end evidence. Cleanup proof and an explicit later reviewed re-enablement are prerequisites to exposing the live workflow. No new failure probes, multipart adoption, backend replacement, hosted changes or physical trials are authorized by this decision.
- Keep #30 as a child of #10 and complete it last. F3–F8 may proceed against the [verified upload-disabled F2 milestone](../implementation/issue-30-disabled-media-acceptance.md), without waiting for full #30 closure; their other capability prerequisites remain. Full #30 stays open for supported cleanup and enabled qualification and is the final blocker to #10 closure. F8 may complete fresh-schema, retirement and integrated acceptance for the upload-disabled state using the verified disabled F2 milestone and other prerequisites. Full media transfer/cleanup/private-delivery/playback proof remains deferred to #30 and parent #10 closure, rather than blocking F8 completion or being waived. Preserve current guards, private access and prior-authorized cleanup-pending safety. F8 records only its disabled-scope acceptance, never final #10 acceptance; rerun affected integration/fresh-schema/current #9 checks after later F2 changes before #10 closure. ADR-0031's allowance for a runtime release with uploads unavailable does not waive this #10 completion requirement or authorize re-enablement. This ADR records the intended dependency policy; GitHub publication/read-back is recorded separately.
- Current #9 safety/security contracts, #10 complete removal/fresh-schema obligations and mandatory #17/#7 automatic-ejection/recovery and actual-iPad gates remain unchanged.

## Consequences and acceptance

Implementation can advance without enabling media or pretending the cleanup boundary is solved. The [F2 plan](../superpowers/plans/2026-10-24-issue-10-f2-event-preparation-media.md) and [acceptance trace](../implementation/issue-10-retirement-and-acceptance.md#acceptance-trace) retain open proof obligations. The new reminder needs its own UI verification; it is not covered by the older disabled-scope pass. Existing qualification/support/research records and failed evidence remain unchanged.

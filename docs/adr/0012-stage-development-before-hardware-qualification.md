# Stage development before hardware qualification

At this decision, the actual iPad A16 has not yet been purchased and only used film is available. Keep the target-device feasibility gate in [ADR-0005](0005-validate-the-target-booth-browser.md): a full Admin, Booth, and print-accounting build follows a successful trial on the actual iPad, Bluefy, and Mini Link 3. Before that gate, development may implement only independent Admin sign-in and password recovery, Admin navigation, Profile account settings, and Draft Event creation/editing, plus an isolated printer qualification harness and simulated printer tests. Draft deletion waits for the operational decision in [issue #8](https://github.com/noelorph/diy-instax-photobooth/issues/8). This work does not enable Live Event operation, Booth Access Grants, printer-backed readiness or Test Prints, Print or Film Reservations, stock consumption, or Confirmed Print accounting. An iPhone trial and used-film tests may narrow protocol uncertainty but cannot establish fresh-film image quality, reliable physical-ejection feedback, or iPad booth behavior. Record the purchased iPad's exact model and iPadOS version during its trial. This staging allows independent work to progress without treating provisional printer behavior as an accepted system contract.

# Printing qualification milestone — historical prompt

> **Historical input, not an active work order or product specification.** This prompt raised the question of how to begin development before the first-release iPad A16 was available. The agreed answer is recorded in the [PRD](../../PRD.md#3-development-and-launch-feasibility-gates), [architecture](../../ARCHITECTURE.md#8-verification-and-delivery), [design system](../../DESIGN_SYSTEM.md#1-authority-and-scope), and [ADR-0012](../adr/0012-qualify-development-on-iphone-before-ipad-launch.md). Follow those documents and the current GitHub issues if any wording here differs.

## Original question and evidence

The owner could test with an iPhone 15 Plus and Instax Mini Link 3 but did not yet have the first-release iPad A16. The question was whether an iPhone trial could justify building the full Admin and print-accounting system, with a separate iPad trial before launch.

The owner reported Bluefy 3.9.3 and Mini Link 3 firmware 0102(RX). Device, browser, and firmware versions must be verified again during each physical trial. Earlier work in [another photo-booth project](https://github.com/noelorph/diy-souvenir-spot-photobooth) and its [printer session code](https://github.com/noelorph/diy-souvenir-spot-photobooth/blob/95990570b013a37aefb127f9a8ec64a90bbfab7f/src/lib/instax/instax-print-session.ts) offers a protocol hypothesis: a 600 × 800 baseline JPEG upload, an acknowledged `PRINT_IMAGE` command, and a Film Remaining change were observed in a MacBook Chrome run. That evidence does **not** prove correct physical output, reliable film ejection, or iPad support. Use it only as a reference for an isolated trial; do not copy that project's Guest flow or photo-retention behavior.

## Agreed resolution

1. **iPhone development gate — [issue #17](https://github.com/noelorph/diy-instax-photobooth/issues/17).** Build an isolated HTTPS qualification harness for camera capture, Retake, printable crop, printer connection, print command, timestamped status, and a lightweight local allowance counter. With usable fresh film on the iPhone 15 Plus, Bluefy, and Mini Link 3, verify the combined camera, Bluetooth, Guided Access, fullscreen, crop/orientation, three consecutive physical prints, Retake, allowance exhaustion, disconnect recovery, and continuous printer power. Correlate printer feedback with observed physical ejection. A command acknowledgement or Film Remaining change alone cannot confirm a print; ambiguous outcomes remain uncertain. Record qualification sheets manually, outside Event accounting.
2. **Work allowed before that gate.** The independent Admin foundation in [issue #14](https://github.com/noelorph/diy-instax-photobooth/issues/14) may proceed in parallel, along with the isolated harness and simulated printer tests. Live Events, Booth Access Grants, printer-backed readiness and Test Prints, reservations, stock consumption, and Confirmed Print accounting wait for the iPhone gate. The foundation is optional and does not have to finish before the trial.
3. **Open product decisions — [issue #8](https://github.com/noelorph/diy-instax-photobooth/issues/8).** Decide how remote Admin interruption affects an active Guest Session, how an Admin can retry a selected photo after a clear pre-film rejection while sign-in and photo-discard rules apply, and whether a Draft Event with operational records can be deleted. These decisions may be resolved while the iPhone trial proceeds. They and the passed iPhone gate are prerequisites for the accounting and access contracts in [issue #9](https://github.com/noelorph/diy-instax-photobooth/issues/9).
4. **Full build and iPad launch gate.** After #9, build and verify the integrated Admin and Booth flows in [issue #10](https://github.com/noelorph/diy-instax-photobooth/issues/10). The actual iPad A16 trial in [issue #7](https://github.com/noelorph/diy-instax-photobooth/issues/7) remains mandatory before first-release deployment. An iPhone pass permits development; it does not establish iPad support or make an iPhone a supported booth.

The original request was for analysis and a plan before changing implementation files. The later PRD, ADR, and milestone issues now govern the implementation sequence.

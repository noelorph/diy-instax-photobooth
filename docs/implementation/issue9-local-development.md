## Local setup

With Docker available, install the existing lockfile dependencies with `npm ci`, then start this checkout's local stack with `npx supabase start`. Inspect identity and ports with `npx supabase status`; keep credential output private. Before F8, additive development migrations use `npx supabase migration up --local`. Do not run an old migration chain on a project already rebuilt from the new baseline.

Configure ignored `.env.local` with the local API as `NEXT_PUBLIC_SUPABASE_URL`, its publishable/anon key as `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, and its privileged key as server-only `SUPABASE_SECRET_KEY`. Never use a public prefix for the privileged key. Set server-only `ADMIN_AUTH_ORIGIN` to the exact local application origin, such as `http://127.0.0.1:3000`, and keep its `/auth/callback` in Supabase's allowed redirects. No credentials belong in tracked files.

`npm run dev` opens the app on port 3000. Optional trusted-device HTTPS uses `npm run dev:https`, with ignored `certificates/booth-key.pem` and `certificates/booth.pem`; follow [ADR-0013](../adr/0013-use-optional-https-for-local-device-testing.md). Read relevant installed Next.js guides before code changes. Shared UI is `src/components/{ui,shared,layout}` and feature state is under `src/features/`.

Server-only `BOOTH_PRINTER_MODE` accepts `disabled`, `simulated` and `instax-development`. Missing/unknown settings and every production process disable development printing. The old simulator boolean has no fallback. See [ADR-0035](../adr/0035-allow-development-instax-integration.md). Simulator outcomes cannot enable real printing or satisfy #17/#7. Use the [current flow guide](../booth-user-flow.md), not historical operator controls, for target behavior.

For explicit local simulation, start with `BOOTH_PRINTER_MODE=simulated npm run dev` (or `npm run dev:https` with the same environment flag). Restart the server after changing the flag. A setup-readiness HTTP `403` with `qualification_required` means server setup is disabled, not that camera permission failed. Setup stops automatic checks and offers **Retry setup checks** after configuration is corrected. An `access_required` or `operation_forbidden` denial instead requires current Admin access; sign in again and return to the Event. Transient network/server faults and stale-readiness conflicts continue to retry. This setting never bypasses the independent owner-controlled database completion-policy gate. New work needs both modes to agree; migrations leave the database policy disabled. The approved physical development setting is `BOOTH_PRINTER_MODE=instax-development`, restricted to FI033/0102 with the pinned development policy. The feature branch now selects the physical adapter with no simulator fallback. For a separately authorized local device session, use `BOOTH_PRINTER_MODE=instax-development npm run dev:https` and the existing trusted-device HTTPS/Bluefy setup. This documentation does not authorize a physical trial. Required database/browser acceptance is still outstanding; see [current integration status](real-instax-booth-integration.md). Automatic reload needs a closed baseline captured for that exact request; missed, expired or interrupted observation requires authenticated phone confirmation. No owner environment file or database policy is changed by setup instructions. Nonproduction outcomes from already-authorized work retain their pinned reconciliation path after either mode changes; production still rejects fresh development evidence.

## What the existing evidence establishes

The [dated issue #17 report](issue-17-trial-report.md) preserves October observations; the [November 6 report](2026-11-06-ejection-detection-trials.md) records the later successful detection milestone and its limits. The October 2026 setup was iPhone 15 Plus, iOS 26.2.1, Bluefy 3.9.3, Mini Link 3 FI033 firmware 0102(RX). Record versions afresh in future trials. The following bullets describe the earlier evidence.

- Supervised camera/capture/Retake, connection and direct printing worked in that setup. Seven fresh-film prints matched the reviewed crop/orientation.
- A separate three-used-sheet sequence demonstrated Retake and exhaustion of the **old local harness limit**. The operator reported the next print blocked; supplied logs show no fourth command. This does not prove the new package model or image quality on fresh film.
- A one-used-sheet experiment reported ten sheets before and nine after ejection with none known physically remaining. The counter is not inventory or reliable proof of a newly loaded ten-sheet pack.
- Candidate status changes/count drops and operator timing did not establish reliable automatic **full** ejection. The original complete fresh-film sequence remained incomplete. No separate Link 3 notification proving ejection was observed.
- Existing simulator tests are software evidence for the historical model only. Neither simulation nor manual observation taps qualify automatic success, no-film diagnosis, safe reconnection, this new recovery contract or an actual iPad.

Dated statements about what film was loaded describe those trials, not the printer's current state. Preserve original logs/video and distinguish physical observation from interpretations.

## Evidence record for each new trial

Record case ID, date/time, operator, commit/configuration, adapter/evidence-policy version, exact device/browser/OS/printer firmware, physical fresh/used/empty film condition, starting Event capacity and attempt state, actions/timestamps, expected outcome, actual sheet output with synchronized video, safe protocol logs, server receipts/counters, pass/fail and deviations. Record failures as well as successes. Redact secrets/contacts; never capture/store Guest photos in application telemetry. Use consented calibration/trial images and maintain trial evidence separately from production Guest data.

P1 qualification must document its observation precision and explain why candidate status cannot indicate success early. Define a repeatable physical safe-clearing procedure for P4/P10/P11 before treating Not printed as safe to release. If a procedure cannot reliably resolve a case, record that limitation and keep the booth blocked for that case.

The [older runbook](issue-17-runbook.md) describes existing harness controls and dated procedures. It is historical reference; it must be adapted in a later implementation/trial change before executing this checklist. This document neither sends printer commands nor authorizes unattended hardware operation.

# Instrumentation stage gate

The original image is immutable. This separate image changes only `dist/storage/protocols/s3/s3-handler.js` and adds `/app/qualification-hook.cjs`; the patch adds one awaited call immediately before `createMultipartUpload` records a session. The existing backend creation has already returned. No cleanup, authorization, RLS, existing error handler, transaction, lock or successful response is changed. This models a failed persistence boundary, not an actual database crash. The added async no-op introduces a microtask boundary even when unarmed; disabled-control evidence therefore remains separate from original-image evidence.

Control files live on their own `/qualification-control` volume, outside `/mnt`. The arm file is consumed once, the reached marker is written, then the hook throws. Without the arm file, the hook returns. No database triggers, session cancellation or advisory-lock machinery are added.

Planned order: run original-image ordinary transfer/validation, response-loss reconciliation, interrupted/resumed part, pagination and capability denials. Run the same harness on the derived image with no arm file. Only after the controller's review, arm the one-shot creation-persistence error, call CreateMultipartUpload, assert the reached marker, and inspect public inventories plus all `/mnt` files. Abort via any recovered supported inventory; use DeleteObject; retry part/completion/abort for the read-only observed upload ID to test inaccessible residual metadata. Require every file absent before teardown. A residual inaccessible metadata file fails a prerequisite and stops dependent concurrency/race expansion. Those cases will remain explicitly NOT RUN. No artifact removal by Docker teardown counts as cleanup proof.

Before execution, compare recursive file hashes from exported original and instrumented root filesystems: expected differences are exactly the vendor handler and added hook. Run matching controls before arming. The source hash manifest and patch permit independent read-only review now; image identity and filesystem-difference evidence follow build.
